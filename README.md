# 📱 AI App Usage Pattern Analyzer

A data science project that analyzes mobile app usage data, groups users into behavioral segments using **K-Means clustering**, and presents the results in an interactive **analytics dashboard**.

## Problem Statement
Built-in tools such as Digital Wellbeing and Screen Time only show *descriptive* data ("you used your phone for 5 hours today"). They do not tell you **what type of user you are** or how your habits compare with others. This project extracts **behavioral patterns and user groups** from raw usage data.

## Objectives
1. Clean raw usage data and engineer meaningful per-user features.
2. Segment users into groups with unsupervised learning (K-Means).
3. Give each group an understandable name and plain-language insights.
4. Present everything in an interactive dashboard.

## Tech Stack
Python · Pandas · NumPy · Scikit-learn (K-Means, PCA, Silhouette score) · Matplotlib / Seaborn · Plotly · Streamlit

## Dataset
Synthetic data generated by `generate_data.py`: 200 users × 30 days ≈ 125,000 sessions, with 4 hidden user types (heavy social, productive, night owl, casual).

| Column | Description |
|---|---|
| `user_id` | Unique user identifier |
| `app_name` | App used |
| `category` | Social, Entertainment, Games, Productivity, Education |
| `start_time` | Session start timestamp |
| `duration_min` | Session length in minutes |

> A real dataset (e.g., from Kaggle or a Digital Wellbeing export) in the same format will work with the same pipeline.

## Methodology
| Step | Script | Purpose |
|---|---|---|
| 1 | `generate_data.py` | Generate synthetic usage data |
| 2 | `step3_eda.py` | Cleaning (missing values, duplicates, outliers) and EDA charts |
| 3 | `step4_features.py` | Per-user features: screen time, night usage %, category share, peak hour, weekend difference |
| 4 | `step5_clustering.py` | Scaling → Elbow / Silhouette → K-Means (K=4) → PCA plot |
| 5 | `step6_profiling.py` | Cluster naming, profiles, radar chart, insights |
| 6 | `app.py` | Streamlit dashboard (4 pages) |

### Key design decisions
- **StandardScaler:** K-Means is distance-based, so features on larger scales must not dominate.
- **Peak hour encoded with sin/cos:** hour of day is circular (23:00 and 00:00 are one hour apart).
- **`avg_session_min` dropped:** it was nearly identical across users and added no information.
- **K = 4:** Silhouette scores for K=4 (0.593) and K=5 (0.597) were almost equal; K=5 split one group into two indistinguishable halves, and K=4 is easier to interpret.

## Results
| Cluster | Highlights |
|---|---|
| Productive / Study | Productivity apps 2.4x the average; social share only ~10% |
| Night Owl | ~82% of usage between 10 PM and 5 AM (average: 26%) |
| Heavy Social | ~7.3 hours/day; social share ~55% |
| Casual / Light | ~1.9 hours/day; no extreme patterns |

## Dashboard Pages
- **Overview:** KPIs, category share, top apps
- **Usage Patterns:** hourly usage, day × hour heatmap, weekday vs weekend
- **Clusters:** PCA scatter plot, radar comparison, cluster profiles, insights
- **My Type:** pick a user to see their cluster, top app, comparison with their group and everyone else, and personal insights

## Limitations
- The data is synthetic, so clusters are cleaner than they would be on real data.
- Cluster naming rules are fixed and may need adjusting for real datasets.
- "My Type" works only for existing users; uploading new data is not yet supported.
